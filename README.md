# 🎮 ISAAC ARCHIVE

**The Binding of Isaac 팬메이드 게임 데이터베이스 및 공략 플랫폼**

아이작의 번제(The Binding of Isaac)에 등장하는 아이템, 캐릭터, 장신구, 카드, 룬, 보스 등의 게임 정보를 체계적으로 관리하고, 아이템 시너지와 개인 플레이 기록을 분석할 수 있는 웹 플랫폼입니다.

---

## 1. 프로젝트 소개

ISAAC ARCHIVE는 아이작의 번제 게임 데이터를 한곳에서 검색하고 관리할 수 있도록 제작하는 팬메이드 데이터 플랫폼입니다.

게임 내 다양한 정보를 데이터베이스화하고, 사용자가 자신만의 게임 컬렉션과 플레이 기록을 관리할 수 있도록 하는 것을 목표로 합니다.

### 주요 목표

- 아이템 및 게임 정보의 체계적인 데이터 관리
- 아이템 간 시너지 정보 제공
- 캐릭터별 능력치 및 해금 정보 관리
- 개인별 아이템 컬렉션 관리
- 게임 플레이 기록 저장 및 분석
- 사용자 간 빌드 및 공략 공유

## 5. 인증 및 회원 관리 설계

ISAAC ARCHIVE는 일반 로그인과 소셜 로그인을 함께 지원합니다.

### 로그인 방식

| 로그인 방식 | 인증 정보 |
|---|---|
| 아이디 로그인 | LOGIN_ID + PASSWORD |
| 이메일 로그인 | EMAIL + PASSWORD |
| Google 로그인 | Google OAuth2 |
| Kakao 로그인 | Kakao OAuth2 |

### 인증 처리 구조

- Spring Security를 이용한 인증 및 권한 관리
- JWT Access Token 발급
- JWT Refresh Token 발급 및 재발급
- BCrypt를 이용한 비밀번호 해싱
- Refresh Token SHA-256 해시 저장
- HttpOnly 쿠키를 이용한 Refresh Token 관리

### 인증 보안 원칙

- 비밀번호 원문을 데이터베이스에 저장하지 않습니다.
- Refresh Token 원문을 데이터베이스에 저장하지 않습니다.
- Access Token과 Refresh Token의 만료 시간을 분리합니다.
- Refresh Token Rotation 및 폐기 처리를 구현합니다.
- 소셜 계정은 이메일이 같다는 이유만으로 자동 연결하지 않습니다.

## 6. Oracle Database 설계

### 데이터베이스 계정

프로젝트 전용 데이터베이스 계정:

```text
ISAAC_APP
```

일반 애플리케이션 계정은 CDB$ROOT가 아닌 실제 PDB 내부에서 생성하는 것을 원칙으로 합니다.

### 사용자 생성 SQL

```sql
CREATE USER ISAAC_APP
IDENTIFIED BY "직접_설정한_비밀번호"
DEFAULT TABLESPACE USERS
TEMPORARY TABLESPACE TEMP;

GRANT CREATE SESSION TO ISAAC_APP;
GRANT CREATE TABLE TO ISAAC_APP;
GRANT CREATE SEQUENCE TO ISAAC_APP;
GRANT CREATE VIEW TO ISAAC_APP;
GRANT CREATE PROCEDURE TO ISAAC_APP;

ALTER USER ISAAC_APP
QUOTA 500M ON USERS;
```

※ 위 SQL은 일반 Oracle Database 설치 환경을 기준으로 작성했습니다. Autonomous Database 등에서는 별도 설정이 필요할 수 있습니다.

### 회원 테이블 USERS

회원의 공통 정보를 관리하는 핵심 테이블입니다.

```sql
CREATE TABLE USERS (
    USER_ID          NUMBER(19)
                     GENERATED BY DEFAULT AS IDENTITY
                     PRIMARY KEY,

    LOGIN_ID         VARCHAR2(50),
    EMAIL            VARCHAR2(255) NOT NULL,
    PASSWORD_HASH    VARCHAR2(255),
    NICKNAME         VARCHAR2(50) NOT NULL,
    PROFILE_IMG_URL  VARCHAR2(500),

    ROLE             VARCHAR2(20)
                     DEFAULT 'ROLE_USER' NOT NULL,

    STATUS           VARCHAR2(20)
                     DEFAULT 'ACTIVE' NOT NULL,

    CREATED_AT       TIMESTAMP
                     DEFAULT SYSTIMESTAMP NOT NULL,

    UPDATED_AT       TIMESTAMP
                     DEFAULT SYSTIMESTAMP NOT NULL,

    LAST_LOGIN_AT    TIMESTAMP,

    CONSTRAINT UK_USERS_LOGIN_ID
        UNIQUE (LOGIN_ID),

    CONSTRAINT UK_USERS_EMAIL
        UNIQUE (EMAIL),

    CONSTRAINT CK_USERS_ROLE
        CHECK (ROLE IN ('ROLE_USER', 'ROLE_ADMIN')),

    CONSTRAINT CK_USERS_STATUS
        CHECK (STATUS IN ('ACTIVE', 'SUSPENDED', 'DELETED'))
);

COMMENT ON TABLE USERS
IS '회원 기본 계정 정보';

COMMENT ON COLUMN USERS.LOGIN_ID
IS '일반 로그인용 아이디 (소셜 전용 계정은 NULL)';

COMMENT ON COLUMN USERS.PASSWORD_HASH
IS 'BCrypt 해시 비밀번호 (소셜 전용 계정은 NULL)';
```

### USERS 컬럼 설명

| 컬럼 | 데이터 타입 | 설명 |
|---|---|---|
| USER_ID | NUMBER(19) | 회원 고유 식별자 |
| LOGIN_ID | VARCHAR2(50) | 일반 로그인용 아이디 |
| EMAIL | VARCHAR2(255) | 회원 이메일 |
| PASSWORD_HASH | VARCHAR2(255) | BCrypt 비밀번호 해시 |
| NICKNAME | VARCHAR2(50) | 회원 닉네임 |
| PROFILE_IMG_URL | VARCHAR2(500) | 프로필 이미지 주소 |
| ROLE | VARCHAR2(20) | 회원 권한 |
| STATUS | VARCHAR2(20) | 회원 상태 |
| CREATED_AT | TIMESTAMP | 데이터 생성 시각 |
| UPDATED_AT | TIMESTAMP | 데이터 수정 시각 |
| LAST_LOGIN_AT | TIMESTAMP | 마지막 로그인 시각 |

### 제약조건(CONSTRAINT)

| 제약조건 | 역할 |
|---|---|
| PRIMARY KEY | 회원 고유 번호 보장 |
| UK_USERS_LOGIN_ID | 로그인 아이디 중복 방지 |
| UK_USERS_EMAIL | 이메일 중복 방지 |
| CK_USERS_ROLE | 허용된 권한 값만 저장 |
| CK_USERS_STATUS | 허용된 계정 상태만 저장 |
| NOT NULL | 필수 컬럼의 NULL 입력 방지 |

#### UNIQUE

```sql
CONSTRAINT UK_USERS_LOGIN_ID UNIQUE (LOGIN_ID),
CONSTRAINT UK_USERS_EMAIL UNIQUE (EMAIL)
```

아이디와 이메일의 중복을 방지합니다.

Oracle UNIQUE 제약조건은 NULL을 허용하므로 소셜 전용 회원처럼 LOGIN_ID가 NULL인 데이터도 여러 건 저장할 수 있습니다.

#### CHECK

```sql
CONSTRAINT CK_USERS_ROLE
CHECK (ROLE IN ('ROLE_USER', 'ROLE_ADMIN')),

CONSTRAINT CK_USERS_STATUS
CHECK (STATUS IN ('ACTIVE', 'SUSPENDED', 'DELETED'))
```

데이터베이스에 허용된 값만 저장하도록 제한합니다.

| ROLE | 설명 |
|---|---|
| ROLE_USER | 일반 사용자 |
| ROLE_ADMIN | 관리자 |

| STATUS | 설명 |
|---|---|
| ACTIVE | 정상 이용 |
| SUSPENDED | 이용 정지 |
| DELETED | 탈퇴 상태 |

### 날짜 및 시간 컬럼 설계

| 컬럼 | 의미 |
|---|---|
| STARTED_AT | 게임이나 활동이 시작된 시각 |
| CREATED_AT | 데이터가 생성된 시각 |
| UPDATED_AT | 데이터가 마지막으로 수정된 시각 |

`DEFAULT SYSTIMESTAMP`는 INSERT 시 기본적으로 데이터베이스 서버의 현재 시각을 입력합니다.

단, UPDATED_AT은 UPDATE 시 자동 갱신되지 않으므로 JPA Auditing, `@PreUpdate` 또는 DB 트리거 등을 통해 관리해야 합니다.
